# 栖声 1.0.2 — 正常启动与首次安装分离

1.0.1 在每次启动时先显示安装页面，再执行源码、依赖导入和 CUDA 的完整健康检查。环境正常时页面没有安装日志便会退出，让人误以为再次进入首次引导。1.0.0 执行同类检查时没有窗口，会造成静默等待。

- 正常启动改用独立、简洁的启动页，显示安装记录、运行文件变化、显卡驱动、深度检查或本地服务启动的实际阶段。只有运行环境缺失、损坏或安装中断时才打开安装/修复界面。
- 完整健康检查通过后保存本地快速检查记录。每次重启扫描源码、Python 环境及工具的文件名、大小、修改/创建时间；同时比较安装收据、依赖锁、检查器内容、系统版本与 GPU/驱动身份。未变化时不再导入 ACE/SA3、初始化 CUDA 或重复哈希大型工具。
- 新增、删除、修改运行文件，更新依赖规格/驱动，缓存缺失或损坏都会触发完整复核。安装未完成标记仍直接要求修复。检查期间文件再次变化时不保存有效缓存。
- 新安装完成后即建立缓存，启动复核可直接使用；旧版升级首次运行可能需要一次较长复核。缓存不可写不影响已验证环境运行，但以后仍需完整检查。
- 启动页展示真实检查阶段和已完成检查项目数，不显示猜测的耗时百分比。关闭启动页会取消检查和退出应用；不重复播放首次设置动画。
- 每次启动耗时写入数据目录的 `.log/startup-last.json`，记录健康检查模式、检查耗时和主窗口就绪耗时，方便排查机器间差异。

快速记录是本机性能缓存，不是防恶意篡改的签名机制。Python 自动生成的字节码缓存不参与失效判断；实际依赖导入错误仍由运行时报告。模型生成与音频设备状态不是每次启动的全量验收项目。

继续沿用 1.0.1 的运行目录隔离、原文日志、真实下载进度、硬件门槛与 HF 授权引导。源码与安装包验证结果随 GitHub 预发布版列出；干净系统、新 HF 账号全量模型下载、实体设备和人工听感的验收边界不变，Windows 构建仍未签名。
