# 故障排查、备份与升级

本页适用于 v1.0 / v1.0.1。曲库会按播放次数永久退休删除，不是永久收藏。希望另存的音乐应在退出应用后自行备份。

## 找到数据与日志

新安装的数据在 Electron userData 的 `data` 子目录，通常为 `%APPDATA%\Ambient Music Nonstop\data`；以设置中显示的配置文件路径为准。存在 `D:\AmbMusicNonstop\library.sqlite3` 时继续采用这个旧目录。`AMBIENT_DATA_DIR` 可显式指定其他目录。曲库、模型、图片和自定义环境声还可能使用高级设置指定的独立路径。

数据目录包含 `config.json`、`config.last-good.json`、`library.sqlite3`、`.log`、`library-migration.json`（发生迁移时）和默认 `runtime`。声音服务错误查看 `.log/service.log`；生成任务的详细错误在 `.log/<任务ID>.log`。分享日志前移除个人路径、提示词和账号相关信息。

## 配置恢复

缺失、损坏、不完整或不支持的配置会先保留为 `config.rejected-<摘要>.json`，再采用通过验证的最后良好配置，或者安全默认值。数据库登记的曲库地址优先保留。恢复期间自动补库暂停，启动时会显示提示；确认模型、曲库、配方后按需重新开启。

不要删除数据库来修复配置。退出应用，备份整个数据目录后，可把经过检查的备份配置恢复为 `config.json`。数据库与配置应来自同一份备份，避免曲目路径与文件不一致。

## 安装与运行环境修复

安装需要联网访问 GitHub、PyPI、PyTorch 与 uv 的 Python 下载服务。Windows PowerShell 5.1 以非交互模式执行；不要求预装 Python、uv 或 FFmpeg。安装的版本、源码 revision、SHA-256 和依赖锁文件在 `scripts/runtime-spec.json` 中。

启动会在准备窗口检查安装完成标记、运行环境版本、源码哈希、依赖、FFmpeg 和 CUDA device 0。首次检查可能需要几分钟。失败时进入“安装或修复运行环境”。允许设备检查后重试；驱动不支持 CUDA 时先修复 NVIDIA 驱动，重新安装 Python 不能替代驱动修复。

1.0.1 在当前数据目录的 `runtime` 中准备发行版依赖，不再信任旧 `runtime-location.json` 指向的开发目录；这个旧指针文件保留供诊断，已有模型与曲库地址不变。开发/自动验证如需外部运行环境，应明确设置 `AMBIENT_RUNTIME_DIR`。运行环境路径可在准备窗口展开查看，安装详细日志在该路径的 `.log/runtime-install.log`。

进度条表示当前可计量操作：工具/源码文件下载字节和模型准备字节。解压、依赖构建、导入与 CUDA 检查没有可靠总量时显示活动状态；依赖下载显示实际包完成事件，顶部的步骤数只代表成功完成的步骤。不要把等待中的条形动画当作预计百分比。校验损坏的已有模型后切换下载时，已确认字节数可能回退，这是重新下载损坏文件所致。

安装中关闭窗口会保留 `.runtime-installing`，下次启动进入修复。模型和曲库位于运行环境之外。修复会将旧源码、工具和环境移到 runtime 内的 `.runtime-backups`，然后重建；建议预留至少 25 GB。确认修复、重启、生成均正常并自行备份后，可在应用关闭时删除这个备份目录以回收空间。不要把曲库或模型目录放进 runtime。

启动后持续提示服务失败：查看服务日志；确认数据目录可写、磁盘余量足够、防病毒软件未隔离 EXE/DLL，且完整解压了所有发行文件。不要只复制主 EXE。

## 首曲、模型与环境声

1.0.2 正常启动先做快速变更检查，使用独立启动页，不再显示首次安装界面。完整检查通过后，运行目录中的 `.runtime-health-cache.json` 保存可失效的本地记录；文件、依赖规格、检查器或显卡驱动改变会重新复核。升级后第一次启动或缓存损坏时可能较慢。若需要主动完整复核，退出应用后仅删除该缓存文件即可，不必删除 `runtime.json` 或重新下载模型。耗时与缓存模式见数据目录 `.log/startup-last.json`。

首曲生成失败时可在原路径重试；应用仅接纳自己先前创建的空曲风目录，不覆盖无关文件。只有通过正式 QC 并入库后才会完成向导，同时开启自动补库。之后可以在设置中暂停，重启不会覆盖主动暂停。

SA3 需要各用户自行接受模型条款并获得仓库读取权限。Token 仅用于本次下载；应用不会把它保存到配置。下载分片保留供重试，校验失败的分片重新下载。不要把 Token 粘贴到工单或日志。

“仅校验已有模型”仍会联网读取固定 revision 的文件清单，也仍需要相应模型权限；通过校验的本地权重不会重新下载。CUDA OOM 时先检查其他程序的显存占用，并查看任务日志中的实际设备与回退记录。SA3 保留已有的缩短至 120 秒及 CPU 回退策略；这不代表支持纯 CPU 新安装，也不能替代 GPU 路径验收。

环境声支持 2 秒至 3 分钟的导入，解码为 24 kHz、最多双声道。同时保留的环境声解码数据受 192 MiB 限制；关闭声音层后淡出并释放。旧的超长导入仍保留原文件，但需裁剪后重新导入才能播放。

内置录音在启动时按发行清单核验。缺失或损坏会从随应用提供的副本修复；被替换的旧文件保留在数据目录 `Ambience/.recovery`。自定义文件不会因内置素材修复被删除。发行包自身的素材校验失败时，重新解压经 SHA-256 核对的完整发行包。

## 曲库迁移中断

迁移按复制、哈希核验、数据库事务切换、清理旧文件的顺序进行。切换前失败继续使用原库；切换后中断会先完成恢复清理，再进入普通设置。复制或清理出错会显示原因，修复磁盘空间、权限或占用后，可对同一目标重试。

迁移两端不支持符号链接或 Windows 目录联接。不要手工修改迁移日志，不要手工删除两端文件。损坏日志会保留为 `library-migration.rejected-<摘要>.json`；此时不自动清理两端，使用数据库登记的曲库，并提示人工检查备份。

## 完整备份与升级

1. 让生成或迁移结束，退出应用，确认后台服务退出。关闭应用后复制 SQLite 主文件及仍存在的 `-wal`、`-shm` 文件；不要只复制正在写入的数据库。
2. 备份整个数据目录、当前曲库和外部图片/环境声目录。记录模型目录；模型可另备份，或按固定 revision 重新下载。
3. 将新版本解压到新的应用目录，保留旧版本目录作回退。使用同一个 Windows 账号与原数据位置启动，勿同时运行两个版本。
4. 新版会同步所选 runtime 中的应用后端；runtime 规格变化时会进入修复。检查保留的曲库路径、数量、曲风、补库开关，播放一首，再观察一次补库。
5. 如需回退，退出新版，恢复同一次备份的数据及曲库，再启动旧版。仅回退 EXE 无法撤销数据库或配置的升级。

日志、runtime 缓存和备份属于本机资料，均不应上传为公开源码。
