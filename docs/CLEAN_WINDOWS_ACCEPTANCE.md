# v1.0 干净 Windows / NVIDIA 验收

状态：**待人工验收**。开发机的隔离目录、收窄 PATH 和自动测试不能证明干净系统、标准用户、无 D: 盘或真实中文用户名均已通过。

使用一台可提供 NVIDIA CUDA device 0 的干净 Windows 10/11 x64 机器或 GPU 直通虚拟机。创建中文名称的标准用户，不提升权限。仅保留 C: 系统盘，确认未安装 Python、uv、FFmpeg，记录 Windows、PowerShell、驱动、GPU/显存、内存和剩余空间。SA3 至少按应用的 24 GB 内存/6 GB 显存门槛准备，ACE 按 16 GB/4 GB 门槛准备。

## 发行物与安装

1. 将发行 ZIP 和 `SHA256SUMS.txt` 复制到机器。在 PowerShell 执行 `Get-FileHash -Algorithm SHA256 .\Ambient-Music-Nonstop-1.0.2-win32-x64.zip`，与摘要逐字符比对。
2. 解压到中文用户目录中的 `Apps\栖声 Release Test`，运行完整包中的 EXE。记录 SmartScreen/签名提示；当前无代码签名证书的构建不得记为签名通过。
3. 首次拒绝设备读取，确认不能安装且提示明确。再允许并安装，确认不弹 PowerShell 交互确认、不调用系统 Python/uv/FFmpeg、不要求 D: 盘。
4. 在下载过程中关闭窗口，再打开并重试。确认安装完成前不会进入播放器，错误可以重试，模型/曲库未提前创建音乐。记录安装日志与耗时。
5. 完成后退出，将 runtime 中一个已知源码文件改名为 `.acceptance-backup`，再打开。必须显示修复路径。修复后检查运行环境健康、备份保留与重新启动，不得只凭 Python EXE 存在而通过。

## ACE 完整路径

1. 使用全新数据目录，扫描设备，选择 ACE 最小方案并下载/校验模型；选有空格及中文的空曲库目录。
2. 首曲期间暂时使曲库目录不可写（仅该测试目录），观察明确失败；恢复权限，在同一路径重试。若改 ACL 不方便，可使用空间不足的专用测试卷。
3. 首曲必须实际生成并通过 QC 后才能进入播放器；核对任务记录、最终音频哈希、数据库和逐首 sidecar。QC 拒绝不是安装成功的替代证明；保留失败原因，再正常重试。
4. 点击播放，确认声音输出、暂停/恢复、切曲与环境声均正常。确认首次完成后自动补库开启，并实际完成至少一次后续补库。
5. 主动暂停补库，重启后仍应暂停。通过低阈值专用测试库验证完整播放计数与退休删除，禁止使用真实收藏做此测试。

## SA3 完整路径

1. 使用独立数据目录，允许设备检查，确认达到 SA3 门槛。未授权的账号应明确失败且保留下载进度，不能显示为已授权。
2. 用已接受条款、具有读取权限的账号授权，下载与校验。检查 `config.json`、last-good、日志和运行环境收据均无 Token。
3. 生成 SA3 首曲并通过 QC，记录模型 revision、源码 revision、运行设备、时长及回退情况；实际播放，并完成一次补库。
4. 下载中断后重启续传；生成中断后重启，确认任务恢复且旧 `result.json` 不会被误当新结果。完整重启后再次播放和补库。

## 异常与恢复

所有故障注入只在可丢弃的数据目录、曲库或专用虚拟磁盘进行。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 配置损坏 | 退出后分别写入非法 JSON、`null`、`{}`、缺字段对象、未来版本 | 启动恢复提示；原件保留；数据库和已登记曲库未丢失；自动补库暂停 |
| 内置素材损坏 | 删除一个内置 Opus，改坏另一个，再启动 | 自动修复；被替换的原件备份；自定义素材不变 |
| 磁盘满/写失败 | 专用小卷填满；分别在配置保存、模型下载、生成归档、迁移复制时注入 | 明确错误；不发布半成品；原配置/原库可恢复；释放空间后重试成功 |
| 迁移切换前中断 | 迁移至另一个本地卷，在复制时结束测试应用，重启 | 原库仍可用，同一目标可以安全重试 |
| 迁移切换后中断 | 测试库在数据库切换后、旧文件清理前中断 | 恢复页面先于普通设置；内容校验后才清理旧文件 |
| 跨卷迁移 | 添加临时第二卷，将完整测试库迁移到该卷 | 音频与 sidecar 哈希一致，模型/配置原位保留，恢复播放 |
| 日志损坏 | 退出后改坏迁移日志，再启动 | 损坏原件保留，显示恢复提示，两端均不被自动删除 |
| 音频输出 | 播放时断开选定 USB/蓝牙输出，再重连 | 回退系统默认设备，能重新选择输出 |
| 内存限制 | 导入超 3 分钟录音；反复开启/关闭合法环境声 | 超长明确拒绝；关闭后缓存释放；无无声常驻解码层 |

为每项记录 PASS/FAIL、日期、机器配置、复现步骤、日志与截图。任何未执行项保持 PENDING；真实听感、实体音频设备、中文用户账号、标准权限、无 D: 盘和干净驱动环境应由此流程最终确认。

## 1.0.2 启动回归

- 安装成功后退出并连续重启三次，应进入正常启动页和播放器，不出现安装按钮或首次设置动画。记录 `.log/startup-last.json` 的模式和耗时，后续未变化启动应为 `cached`。
- 改名一个已有源码文件后启动：应先复核，随后显示修复原因；还原并重新验证后可建立缓存。增加/修改依赖文件、更新驱动同样必须使缓存失效。
- 删除或损坏 `.runtime-health-cache.json`：只触发完整复核，健康环境不应要求重新安装。保留 `.runtime-installing` 时必须要求修复。
- 完整复核中确认实际阶段与完成项目数更新；关闭启动窗口应取消所属检查进程，且不再打开播放器。

### 1.0.1 界面检查项目

- 在安装窗口与模型向导分别缩小、放大、最大化，展开/收起日志，检查背景完整、无横向溢出，按钮能滚动到达。
- 新桌面配置只播放一次约一秒入场；退出重开与进入模型向导不重复。开启系统减少动画偏好后检查短淡入。
- 工具/源码下载检查实际字节与百分比；缓存命中明确标注。依赖阶段观察真实包完成事件，解压与检查不出现猜测百分比。
- 安装失败可重试；模型校验与下载期间不可更改目录/模型开关；首曲仍受 QC 门槛控制。
- 保留一个指向开发目录的旧 runtime-location.json，再启动发行版；确认运行环境显示为数据目录下的 runtime，旧目录中的哨兵文件不变，原模型和曲库配置保留。
